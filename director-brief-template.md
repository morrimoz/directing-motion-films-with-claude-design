# Director's brief template

Fill in every section before any design work. Paste it as the first message of the Claude Design
project, or keep it as `director-brief.md` in a Claude Code project. An empty section means the gate
has not been passed.

## 1. Film in one line
- **Logline:** what the viewer should believe after one viewing, in one sentence.
- **Stranger test:** "A person who has never heard of [product], watching once with the sound off,
  can say: ________." Write the exact sentence they should be able to say.
- **Audience:** who stops scrolling for this, and why.

## 2. References
- 1-3 reference videos or frames, attached.
- For each one: **take** (palette, type, pacing, transitions, chrome) and **don't take** (subject,
  logo, copy).
- Instruction: *"Extract frames from each reference and describe its pacing shot by shot before
  designing anything."*

## 3. Story and beat sheet
- **Order is chronological for strangers:** setup, then the transformation, then the ongoing value,
  then the invitation, then the sign-off.
- A table with one row per shot: bar or timecode, what is seen (one hero element), the words on
  screen (at most about 5), and the sound cue.
- **A hook in the first 2 seconds.** A visual payoff every 3-5 seconds. The call to action holds for
  at least 1.5s, then the final beat cuts back to frame 1 for the loop. The length is a whole number
  of bars.
- Unknown facts (price, offer, numbers) are written as `[BRACKETS]` until confirmed. Never invent them.

## 4. Locked copy
A table of every on-screen line, exactly as written. **It is re-checked every round.** Mark any
line that makes a product claim, and state the truth it depends on (for example: if a feature only
works on a schedule, never write that it works on demand).

## 5. Visual system
- **Colour fields:** the hex values, which colour carries which chapter, and at most 3 per frame.
- **Type:** the display face, the secondary face and the metadata face, each with a size rule
  (for example: the display face spans 70-90% of the frame width).
- **Chrome:** what sits in each corner of every frame.
- **Hero rule:** one element per frame, filling 60-90% of it; interface only as proof, with at most
  3 lines.
- **Banned:** glow, glass, blur halos, vignettes, constant background texture, crossfades.
- **Signature motif:** where it appears as a hero moment, and nowhere else.

## 6. Motion system
- **BPM,** and the rule that cuts land on beats.
- **Spring profiles** by element class: snappy for interface, default for cards and camera, heavy
  for type and logos, playful for characters.
- **Arrival and exit grammar:** for example, arrival in 8-12 frames with overshoot, a crisp hold,
  then a hard cut.
- **Render rate:** 60fps.

## 7. Sound
- A licensed track (source, BPM, measured cut points), or a synthesised score on the same grid.
- The key sound moments, with timecodes.
- Where the voiceover lives, if there is one: the ducked passages.

## 8. Assets manifest
Every file uploaded, with its intended slot. Real-footage slots carry an ID, a length and an aspect
ratio, and are placeholders until the files are supplied. **Nothing is referenced by a local file path.**

## 9. Formats and safe zones
- **16:9 and 9:16 are composed natively,** never cropped.
- **9:16 safe zone:** text and key visuals sit between 6% and 86% of the width, and between 15% and
  78% of the height, clear of the Reels and TikTok interface.

## 10. Honesty
Every claim must be true of the product today. Any output shown as "made by [product]" must actually
be made by it. Never invent metrics, customers, testimonials or prices.

## 11. Gates and deliverables
The gates: route, brief, reference, assets, style frames, animatic, full pass, sound, ship.

The deliverables:
- Full-resolution MP4s with audio, in each aspect
- A loop check
- A poster frame or thumbnail for each aspect
- A contact sheet
- The source, with a README
